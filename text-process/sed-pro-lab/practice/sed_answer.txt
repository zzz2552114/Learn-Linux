二、完整题解（含题目、答案、预期结果、解释、用途）

1. 只打印指定行范围

题目：
打印 logs/app.log 的第 1 行到第 5 行。

答案 / 命令：
sed -n '1,5p' logs/app.log

预期结果：
2026-07-03T08:00:01+09:00 INFO api app started env=dev version=1.4.2
2026-07-03T08:00:02+09:00 DEBUG api loading config file=/etc/app/app.conf
2026-07-03T08:00:05+09:00 WARN api cache miss user_id=42
2026-07-03T08:00:07+09:00 ERROR api database timeout host=db01.example.com duration_ms=3100
2026-07-03T08:00:08+09:00 ERROR payment payment failed order_id=ORD-20260703-0001 status=502

解释：
-n 关闭自动打印；1,5 是行号地址范围；p 是 print，只打印当前 pattern space。整条命令表示：只输出第 1 到第 5 行。

实践用途：
查看日志或配置文件的局部片段，避免一次输出太多内容。

------------------------------------------------------------------------

2. 替换每行第一个匹配项

题目：
把 conf/app.conf 里 APP_ENV = dev 改成 APP_ENV = prod，但先不要真的改文件，只在终端预览结果。

答案 / 命令：
sed 's/^APP_ENV[[:space:]]*=[[:space:]]*dev/APP_ENV = prod/' conf/app.conf

预期结果：
# Application config
APP_ENV = prod
DEBUG = true
TIMEOUT = 30
LOG_LEVEL=debug
DATABASE_URL=postgres://app:secret@db01.example.com:5432/app
PASSWORD=plain-text-demo
API_KEY=sk_live_demo_123
EMPTY_VALUE=
# CACHE_ENABLED=false
CACHE_ENABLED=true

解释：
s/旧/新/ 是替换命令；^ 锚定行首；[[:space:]]* 匹配 0 个或多个空白；这里只改命中的配置项，不写回文件。

实践用途：
改配置时要精确命中配置名，避免把别处的 dev 误改成 prod。

补充检查 / 注意点：
原文答案正确；补充点：如果要保留原来的空格风格，可写成 sed -E 's/^(APP_ENV[[:space:]]*=[[:space:]]*)dev/\1prod/' conf/app.conf。

3. 全局替换一行里的所有匹配项

题目：
把 data/users.csv 里所有 example.com 替换成 internal.local，只预览，不写回文件。

答案 / 命令：
sed 's/example\.com/internal.local/g' data/users.csv

预期结果：
id,name,email,role,last_login
1,Alice,alice@internal.local,admin,2026-07-01
2,Bob,bob@internal.local,user,2026-07-02
3,Charlie,charlie@internal.local,user,never
4,Diana,diana@example.org,ops,2026-07-03

解释：
\. 表示真正的点号；g 是 global，表示一行内所有匹配都替换；没有 g 时每行只替换第一个匹配。

实践用途：
批量改域名、路径、标识符时非常常用。

4. 删除空行和注释行

题目：
从 conf/app.conf 中删除空行和以 # 开头的注释行，只输出有效配置。

答案 / 命令：
sed -E '/^[[:space:]]*($|#)/d' conf/app.conf

预期结果：
APP_ENV = dev
DEBUG = true
TIMEOUT = 30
LOG_LEVEL=debug
DATABASE_URL=postgres://app:secret@db01.example.com:5432/app
PASSWORD=plain-text-demo
API_KEY=sk_live_demo_123
EMPTY_VALUE=
CACHE_ENABLED=true

解释：
-E 使用扩展正则；/正则/d 表示匹配该正则的行就删除；^[[:space:]]*($|#) 匹配空行或注释行。

实践用途：
快速查看真正生效的配置，过滤掉空行和注释噪音。

------------------------------------------------------------------------

5. 只打印 WARN、ERROR、FATAL 日志

题目：
从 logs/app.log 中只打印包含 WARN、ERROR、FATAL 的行。

答案 / 命令：
sed -n -E '/WARN|ERROR|FATAL/p' logs/app.log

预期结果：
2026-07-03T08:00:05+09:00 WARN api cache miss user_id=42
2026-07-03T08:00:07+09:00 ERROR api database timeout host=db01.example.com duration_ms=3100
2026-07-03T08:00:08+09:00 ERROR payment payment failed order_id=ORD-20260703-0001 status=502
2026-07-03T08:02:10+09:00 FATAL worker out of memory pid=2222
2026-07-03T08:03:01+09:00 ERROR api password reset token leaked? token=abcDEF123456

解释：
-n 关闭默认输出；-E 让 | 表示或者；/WARN|ERROR|FATAL/ 是正则地址；p 打印匹配行。

实践用途：
按关键日志级别快速筛选故障相关日志。

补充检查 / 注意点：
补充：这个命令不会匹配小写 warning；如果需要大小写不敏感，可用 GNU sed 的 I 标志或先统一大小写。

6. 删除 DEBUG 行和健康检查行

题目：
从 logs/app.log 中删除包含 DEBUG 的行，也删除包含 health check 的行。

答案 / 命令：
sed -E '/ DEBUG /d; /health check/d' logs/app.log

预期结果：

解释：
分号 ; 分隔多个 sed 命令；/ DEBUG /d 删除日志级别为 DEBUG 的行；/health check/d 删除健康检查行。

实践用途：
排障时过滤调试日志和探针日志，留下更有价值的业务日志。

补充检查 / 注意点：

7. 日期格式转换

题目：
把 data/report.txt 里的日期从 YYYY-MM-DD 改成 DD/MM/YYYY，只预览，不写回文件。

答案 / 命令：
sed -E 's/([0-9]{4})-([0-9]{2})-([0-9]{2})/\3\/\2\/\1/g' data/report.txt

预期结果：
Report date: 03/07/2026
Backup window: 03/07/2026 02:00-03:00
Owner: ops@example.com
Ticket: INC-20260703-0007

解释：
-E 启用扩展正则；三个括号分别捕获年、月、日；\1、\2、\3 是反向引用；g 表示每行多个日期都转换。

实践用途：
日志清洗、报表转换、字段重排时非常常用。

8. 在匹配行前插入一行

题目：
在 conf/nginx.conf 中每个 server { 前面插入一行注释：# managed by sed lab。只预览，不写回文件。

答案 / 命令：
sed '/server {/i\ # managed by sed lab' conf/nginx.conf

解释：
地址 /server {/ 命中包含 server { 的行；i\ 文本表示在匹配行之前插入文本。

实践用途：
自动给配置块、函数、关键段落加注释或标记。

补充检查 / 注意点：
GNU sed 支持这种一行写法；更可移植的写法是把 i\ 后面的文本放到下一行。

9. 安全地原地修改文件，并创建备份

题目：
把 conf/app.conf 复制到 tmp/app.conf，然后把其中未注释的 DEBUG = true 改成 DEBUG = false。要求真的修改文件，并生成备份。

答案 / 命令：
cp conf/app.conf tmp/app.conf
sed -i.bak -E 's/^(DEBUG[[:space:]]*=[[:space:]]*)true/\1false/' tmp/app.conf
grep -n 'DEBUG' tmp/app.conf tmp/app.conf.bak

预期结果：
tmp/app.conf:3:DEBUG = false
tmp/app.conf.bak:3:DEBUG = true

解释：
-i.bak 原地编辑并生成 .bak 备份；-E 使用扩展正则；捕获组保留 DEBUG = 这一段，只把 true 改成 false。

实践用途：
真实改文件时保留回滚点，尤其适合配置修复。

补充检查 / 注意点：
注意不要写成 sed -ni 且没有 p，否则可能把文件写空。

10. grep + sed：提取 ERROR 日志里的时间和服务名

题目：
先用 grep 找出 logs/app.log 中包含 ERROR 的行，再用 sed 输出这种格式：time=时间 service=服务名。

答案 / 命令：
grep 'ERROR' logs/app.log | sed -E 's/^([^ ]+) ERROR ([^ ]+) .*/time=\1 service=\2/'

预期结果：
time=2026-07-03T08:00:07+09:00 service=api
time=2026-07-03T08:00:08+09:00 service=payment
time=2026-07-03T08:03:01+09:00 service=api

解释：
grep 先缩小范围；sed 捕获第一个字段作为时间，捕获 ERROR 后面的字段作为服务名，然后重排输出。

实践用途：
排障时先过滤、再提取关键字段，这是日志处理的常见组合。

13. Nginx 安全配置修复：关闭 server_tokens

15. 只修改 INI 文件中的 production 区块

题目：
把 conf/system.ini 中 [production] 区块里的 log_level=debug 改成 log_level=warn，不要修改 [development] 和 [staging] 区块。

答案 / 命令：
sed -E '/^\[production\]/,/^\[/ s/^(log_level=).*/\1warn/' conf/system.ini

debug=true
workers=1
[production]

workers=4
[staging]

解释：
地址范围从 [production] 行开始，到下一个 section 行结束；范围内才执行替换；\1 保留 log_level=。

实践用途：
在分 section 的配置文件里只修改指定环境，避免误改开发或测试环境。

补充检查 / 注意点：
这条命令会把下一个 section 标题也纳入范围，但替换正则只匹配 log_level=，所以本数据中安全。

把 data/header.txt 的内容插入到 conf/app.conf 的 # Application config 行后面，只预览。

答案 / 命令：
sed '/^# Application config/r data/header.txt' conf/app.conf

预期结果：
# Application config
# inserted by sed r command
# owner: ops
APP_ENV = dev

# CACHE_ENABLED=false

解释：
r filename 会在当前周期输出之后，把指定文件内容读入输出流。

实践用途：
批量给配置文件插入统一 header、版权说明、模板片段。

39. 补充：用 w 把匹配行写入文件

题目：
把 logs/app.log 中 ERROR 行写入 tmp/errors.log，然后查看 tmp/errors.log。

答案 / 命令：
rm -f tmp/errors.log
sed -n '/ ERROR /w tmp/errors.log' logs/app.log
cat tmp/errors.log

预期结果：
2026-07-03T08:00:07+09:00 ERROR api database timeout host=db01.example.com duration_ms=3100
2026-07-03T08:00:08+09:00 ERROR payment payment failed order_id=ORD-20260703-0001 status=502
2026-07-03T08:03:01+09:00 ERROR api password reset token leaked? token=abcDEF123456

解释：
w filename 把当前 pattern space 写入文件；-n 避免同时打印到终端。

实践用途：
从大日志中抽取子集保存成文件，供后续分析或转交他人。

40. 补充：用 y 做字符级转换

题目：
把 data/packages.txt 中的小写英文字母转换为大写，只预览。

答案 / 命令：
sed 'y/abcdefghijklmnopqrstuvwxyz/ABCDEFGHIJKLMNOPQRSTUVWXYZ/' data/packages.txt

41. 补充：多文件处理时使用 -s 分开计算行号和 $

题目：
同时读取 data/users.csv 和 data/packages.txt，打印每个文件的最后一行。

答案 / 命令：
sed -s -n '$p' data/users.csv data/packages.txt

预期结果：
5,Eve,eve@example.com,guest,never
curl 8.5 installed

解释：
默认多个输入文件会被 sed 看成一条连续流；-s/--separate 让每个文件单独处理，所以 $ 表示每个文件的最后一行。

实践用途：
批量处理多个文件时，避免地址范围或行号跨文件串起来。

42. 补充：用 l 显示不可见字符

题目：
用 sed 显示 data/invisible.txt 中的制表符、行尾和尾随空格。

答案 / 命令：
sed -n 'l' data/invisible.txt

预期结果：

解释：
l 命令以明确形式打印 pattern space，会显示行尾 $，并把制表符等不可见字符转义显示。

实践用途：

43. 补充：GNU sed 的 -z 处理 NUL 分隔数据

题目：
把 data/nul.txt 中 NUL 分隔的 beta 替换成 BETA，并用 tr 把 NUL 显示成换行。

答案 / 命令：
sed -z 's/beta/BETA/' data/nul.txt | tr '\0' '\n'

预期结果：
alpha
BETA
gamma

解释：
-z/--null-data 让 sed 把 NUL 当作记录分隔符，而不是换行；这里用 tr 只是为了看清输出。

实践用途：
和 find -print0、sort -z 等命令配合处理可能含空格或换行的文件名。

补充检查 / 注意点：
这是 GNU sed 扩展。

44. 补充：BRE 基本正则写法和 -E 的区别

题目：
不用 -E，从 data/users.csv 中提取 id 和 name，输出 id=数字 name=姓名；跳过表头。

答案 / 命令：
sed -n '2,$ s/^\([0-9][0-9]*\),\([^,]*\),.*/id=\1 name=\2/p' data/users.csv

预期结果：
id=1 name=Alice
id=2 name=Bob
id=3 name=Charlie
id=4 name=Diana
id=5 name=Eve

解释：
不加 -E 时是 BRE，捕获组要写成 \( ... \)，+ 不能直接用，所以用 [0-9][0-9]* 表示一个或多个数字。

实践用途：
看懂老脚本、跨老系统维护 sed 命令时很重要。

三、这套题最终覆盖的 sed 能力清单

基础输出与过滤：-n、p、d、=、l、地址、地址范围、反选 !。
替换：s///、g、数字标志、p 标志、&、\1-\9、替换分隔符、大小写转换。
正则：BRE、ERE、字符类 [[:space:]]、锚点 ^/$、分组、或 |、转义。
文件修改：-i.bak、备份、grep 检查、批量文件处理。
脚本组织：分号、-e、-f、命令组 { }。
插入与整行处理：i、a、c、r、w。
多行与流程：N、标签 :、b、q、hold space 的 h/G。
GNU sed 扩展：I、\L/\U、-s、-z。
